# 配置、缓存与升级

适合管理此实例的可信管理员：明确配置归属、审核与额度、缓存容量、备份和迁移冲突恢复。日常出图见[使用指南](usage.md)，其他插件开发见[联动指南](integration.md)。

## 配置归属

平台、通用与风格配置使用带缩进的 UTF-8 JSON 文本文件，不保存在数据库中。文件结构、完整示例、重新加载与错误恢复另见[手动编辑配置](manual-configuration.md)。

- **绘图平台**：按需添加实例，在平台窗口点击“保存平台”，保存到标准数据目录 `platforms.json`。
- **偏好与预设**：通用配置、审核配置、风格预设共用草稿，右上角“保存全部设置”统一保存到 `workspace_settings.json`。切换分类保留草稿；离开页面仍有未保存确认。审核仍保存在 `general` 下，已有文件无需拆分或迁移。
- **MaiBot 插件配置页**：`config.toml` 只保留 `plugin`、`proxy`，管理启用开关、网络代理与缓存上限；扩展工作台不重复展示这些项目。

配置位置以 Runner 授予路径为准，常见持久目录是 `data/plugins/maimai-drawpic-plugin/`，临时目录是 `temp/plugins/maimai-drawpic-plugin/`。数据不依赖插件源码目录名。

密钥不回显，编辑时留空保留，清除须显式勾选；平台恢复默认不清除已有密钥。保存采用修订号，多页面或其他管理操作已修改配置时，过期保存会被拒绝。不要为了消除提示直接覆盖旧 JSON。

保存请求超时或被取消，不代表后台提交已取消。已开始的配置事务会继续完成写入与运行时刷新；先重新读取保存状态，避免反复提交。若提示运行时刷新未完成，先检查日志，再重新加载插件恢复，不要仅凭页面显示的新参数判断运行配置已经生效。

## 权限、额度与审核


管理员 ID、群聊与私聊默认额度、周期在“偏好与预设 → 通用配置”中设置，审核开关和审核提示词在“审核配置”中设置。聊天中的额度管理使用 `/绘图 次数` 及其帮助提示。

提示词审核与图片审核分别选择 `replyer`、`planner` 或 `vlm`，默认均为 `vlm`，沿用 MaiBot 中对应任务组的模型配置。图片审核所选任务组中的模型必须支持图片输入；模型不支持、调用失败或结果无法解析时任务会失败，不会自动换组或绕过审核。

两类审核的单次最长等待时间分别设置，默认均为 **60 秒**，范围 **5～600 秒**；图片审核按每张图片、每次尝试计算。模型提前返回就立即继续，无需等满配置时间。审核等待会覆盖 Runner 默认的 30 秒 RPC 等待，与“图片请求超时”分别生效；模型服务自身的超时仍然有效。

提示词和图片审核分别配置重试次数，均默认**额外重试 2 次，最多调用 3 次**，可设 **0～5 次**，0 表示关闭。调用异常、超时、空或格式错误的响应可以重试；明确 REJECT 或取消立即结束，不会反复尝试直到通过。每次重试使用新的单次等待预算，图片只重试同一张图的审核，不重新生图。

聊天工具与指令先创建后台任务，再审核提示词；提交成功表示任务已接收，通过提示词审核后才调用绘图平台。明确拒绝或重试用尽后仍失败的结果不会放行；取消或单次超时后晚到的通过结果也不会补发。已有审核开关和模板在升级时保留。

日志按任务 ID、审核阶段和图片序号记录模型任务组、单次预算、尝试次数、耗时、结果与错误码；配置保存记录审核设置摘要，不记录审核提示词、原始模型响应、图片 Base64 或密钥。

- 启用次数管理后，群聊共享本群额度，私聊按用户计算；管理员不受次数限制。额度周期可按日、周、月或一次性配置。
- 发往聊天的任务在执行前预留一次额度。能力或源图校验拒绝时不扣额度；生成、审核或发送失败且没有任何图片确认送达时，正常结算会退回该次预留。至少一张已确认送达时保留本次消费。
- 预留绑定消费时的实际周期，取消与失败重复结算不会重复退款；跨周期结束的旧任务不抵消新周期的消费。提前取消也会等待预留写入结束后结算。
- 不指定 `stream_id` 的网页/联动管理调用仅生成结果，不使用聊天额度规则。调用方仍需自行验证用户权限。
- 额度文件或磁盘故障需先处理并核对日志；重启不会根据未确认的远端结果自动退款。插件额度与提供商计费相互独立，本地取消、退次数或发送未确认都不表示提供商未收费。

网页与联动入口都属于当前实例的管理能力。仅向可信管理员开放 MaiBot WebUI，仅安装可信插件。联动 API 不提供网络监听、独立令牌、平台密钥读取或任意文件读取功能。调用方插件自行负责其聊天用户的权限检查，不能直接将不可信用户参数作为管理操作。


## 缓存与保留期

在 **MaiBot 插件配置 → 插件基础配置** 中，图片缓存、日志和上传缓存可分别设置容量上限，单位 MB（按 1024² 字节计算）。默认图片 **300 MB**、日志 **10 MB**，保存配置后立即按新上限清理较旧内容，工作台不重复展示这些设置。

| 数据 | 清理策略 |
| --- | --- |
| 上传与输入源图 | 默认合计 256 MB，可独立调整；同时限制 24 小时、100 个文件；领取后移除上传中间文件 |
| 生成原图、WebP 预览与缩略图 | 共用图片缓存上限，默认 300 MB；同时限制 30 天、500 个任务，按最旧任务清理，正在使用的结果受保护 |
| 插件日志 | 当前日志与 3 份轮转备份共用日志上限，默认合计 10 MB |
| 聊天图片内存缓存 | 30 分钟 TTL、条目数量和 256 MiB 编码大小上限，卸载时释放 |
| 任务与网页元数据 | 最多 500 条任务记录，清理已淘汰任务的网页元数据 |

生成图片缓存位于 Runner 授予的 `temp/plugins/maimai-drawpic-plugin/results/`，旧数据目录中的图片缓存仍可读取，并计入同一上限。在启动、写入相关缓存时检查限制，并每 10 分钟清理过期产物。图片被清理后任务状态仍可查询，但原图与预览不再可读。单次结果超过缓存容量时会说明未缓存原因，不重新请求生图，聊天图片仍正常发送。用户工作流、密钥配置、额度记录及迁移备份不会被当作缓存删除。

### 图片处理与日志内存限制

磁盘缓存容量与处理内存的安全预算分别管理。插件对每次提供商结果固定限制为：

- 最多 **16 张**图片，压缩图片字节合计最多 **100 MiB**，单张最多 **25 MiB**。
- 单张任一边不超过 **8192** 像素，面积不超过 **16,777,216** 像素（4096 × 4096）；一次结果合计不超过 **67,108,864** 像素。
- 收集图片时逐张检查，解码与生成预览前再次验证。超出这些处理预算会拒绝该结果，不发送截断后的部分图片，也不重新绘图；提供商仍可能已经计费。

这些是插件安全预算，不是提供商所宣称的最大分辨率，也不是严格的进程 RSS 上限。SDK 可能在返回结果前自行缓冲响应，解码也有临时内存；大批量 ComfyUI 工作流应控制输出数量和尺寸。调整磁盘缓存上限不会放宽这些处理预算。

插件日志后台队列最多保留 **256 条**记录。磁盘消费过慢时非阻塞丢弃新日志并累计丢弃数量，不让日志无限占用内存；因此日志不是绝不丢失的审计账本。任务记录与幂等信息仍由独立持久化机制管理。


## 升级迁移与冲突恢复

升级前停用或卸载旧运行实例，备份 `config.toml`、完整标准数据目录和需要保留的图片；不要先删除原目录。不要创建两个相同插件 ID 的安装。

首次加载会识别已有平台及通用配置。先保存新数据、按原始字节备份 TOML，再移除迁出的配置节；重启沿用已迁移的内容。没有旧平台时从空列表开始。编辑密钥留空保留原值，也可显式勾选清除。配置采用修订号，多个页面同时编辑时提示刷新。


历史配置版本 `2.37.0`、`2.38.0` 曾可能在升级时把完整默认平台和绘图设置补回 `config.toml`，与工作台 JSON 冲突。更新后重新加载插件即可恢复这种已知情况：只有完整匹配对应版本的默认模板、且两份 JSON 都存在并校验通过时，才按原始字节备份 TOML 到 `migration_backups/config-reseeded-*.toml`，然后移除重复默认节，保留 `plugin/proxy` 与原有工作台配置。恢复不向 JSON 写入默认值；已有提交事务仍按原规则验证并恢复。备份或写入失败时保留原件，下次加载可重试。

如果 TOML 中包含实际修改、缺少模板字段或不属于已知模板，仍按正常迁移规则处理。新 JSON 配置与旧 TOML 内容不同，插件会报告冲突并保留原文件。先备份 `config.toml` 和数据目录：保留工作台配置时移走 TOML 中的旧绘图配置节；恢复旧 TOML 时先移走相应的 `platforms.json` 或 `workspace_settings.json`，再重新加载插件迁移。不要在没有备份时覆盖配置文件。

工作台设置文件升级为带自身修订号的格式；旧格式会先按字节备份再升级，平台密钥仍由 `platforms.json` 保存。平台重命名需同时更新模型引用时，使用 `workspace_config_transaction.json` 保存已提交的完整事务，再同步两个文件。该文件可能含密钥，应和配置采用相同的保管方式，不能公开或当缓存删除。

若界面提示“配置已保存，文件同步尚未完成”或“运行时刷新未完成”，说明提交已成功，不应当作普通保存失败反复提交。先检查磁盘和日志，再重新加载插件完成恢复；事务与目标文件冲突时会保留原件并拒绝覆盖。存在待恢复事务时，应一起备份事务文件与两个配置文件，先解决恢复问题，再按上面的旧配置迁移步骤操作，不要单独删除事务或改写其中一个文件。


旧插件目录中的 `data/` 及历史状态文件会校验后迁移，内容冲突时报错并保留原件。迁移备份包含原有密钥，应与数据目录一起妥善保管。

旧模型分组、审核与统一额度字段会先按相同规则归一化，再迁移或比较配置；写入中断后重新加载可继续完成迁移。迁移期间若检测到 TOML 被外部修改，会停止清理并保留文件；应停用旧实例后再编辑或升级。取消加载会先等待已经开始的写入完成，再释放资源，防止与回滚同时操作配置。

会话偏好和额度文件损坏、含未知字段或无效记录时，会停止加载并拒绝覆盖原件；请核对备份，修复文件后重新加载。初始化失败不会以空状态保存覆盖这些文件。平台暂时禁用、模型暂不可用或短名变得有歧义时，保存的会话模型选择仍保留；使用时会提示重新选择，也可在修复平台后继续使用。


任务与幂等映射现在保存在同一个任务文件中，先原子写入再启动绘图。旧 `workspace_tasks.json` 保留读取兼容；新任务不依赖它作为唯一幂等索引。重启时未完成的任务记为待确认，不自动重放，先核对提供商记录。任务文件损坏时停止加载并保留原件，请从备份恢复，不能清空文件来假装消除问题。

如果图片已生成或发送，但任务终态暂时无法写盘，插件会保留已知结果并提示终态尚未落盘，恢复磁盘后通过查询或卸载补写，不重新绘图或发送。尚未保存的状态无法保证跨进程崩溃保留，应先修复存储故障并核对提供商、聊天记录。

迁移备份不会作为缓存自动清理；它们包含旧密钥，应由管理员定期核对并妥善保管。

## 请求与安全边界

默认首选模型与默认风格使用下拉选择，备选模型按需添加并可上移、下移。“最多重试次数”默认 1、最多 5，可选 0 关闭；已有明确设置不会覆盖。仅对连接未建立、明确限流等可安全重试的失败生效；认证、参数和配额拒绝可按顺序改用备选，但不重复请求同一模型。审核拒绝、生成结果解析/下载失败，以及超时等远端受理状态不确定的情况均不自动重绘。恢复默认先回填当前分类，保存后生效，其他标签页草稿与已有密钥保留。

“仅支持文生图模型”和“仅支持图生图模型”使用按需添加的下拉列表，支持选择多个模型并逐项移除；已有未匹配模型保留，人工限制优先于自动判断。

ComfyUI 和阿里云异步任务取得远端 ID 后，查询短暂断线只会重试同一 ID，单次查询最多尝试 3 次，仍受平台尝试总超时限制。查询重试耗尽时错误消息保留远端 ID，不重新排队或切换备选模型；若总超时提前结束本地等待，可从任务日志查找已提交的远端 ID。远端任务仍可能继续执行。

图片结果下载仅允许 HTTP(S)，禁止地址内嵌凭据，并逐跳检查重定向。直连默认在本地解析 DNS、检查全部 IP 并固定连接目标；阻止内网、回环和链路本地地址，管理员所配置服务的**相同协议、主机及端口**除外。API 和图床域名不同本身不会被阻止。

实际使用手动代理或系统 HTTP(S) 代理时，保留图片原始域名，由配置的代理解析 DNS 并负责域名的访问控制，避免本地 Fake-IP、DNS 不可用或把域名改成 IP 导致下载失败；显式的非公网 IP 与 localhost 地址仍会检查。每次重定向都会重新选择代理，系统代理的 `NO_PROXY` 以及“绕过国内平台”导致的直连仍保留完整 IP 校验。

“偏好与预设 → 通用配置 → 忽略图片地址 IP 校验”对应 `general.skip_image_url_ip_check`，默认关闭。只有可信服务确实使用跨域内网图床、特殊 DNS 或仅有 TUN/Fake-IP 的透明代理时才开启；开启后不再检查结果地址的 IP 范围或内网同源限制，也不固定连接 IP。HTTP(S) 格式、地址凭据、每次跳转、最多 5 次重定向及图片内容/大小校验仍然生效。该选项保存到 `workspace_settings.json`，无需修改宿主配置。

平台 API 地址应填写最终服务地址，生成请求与模型查询不会自动跟随重定向。


原图与结果传输短暂失败只恢复原结果读取，不能因此重新生成。查询重试耗尽会携带远端 ID；总超时提前中止时，可从任务提交日志查找 ID。上游受理状态未知与“明确未发出”不同，不承诺 exactly-once。

网络代理在宿主插件配置中管理。私有 WebUI API 可编辑配置并查询日志，公开联动接口不提供平台密钥、配置写入、原始日志或任意路径读取。不开放独立 HTTP 服务或令牌。仅安装可信插件并限制 WebUI 管理员访问。

工具、命令与失败通知共用脱敏规则；意外内部异常会返回安全提示和诊断编号，可据此查找脱敏日志。提交错误信息求助前，仍应自行检查截图和日志是否包含私人提示词、会话信息或其他不应公开的数据。
