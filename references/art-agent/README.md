# 绘图编排层 · 参考实现（中性化）

> **这是参考实现，不是可部署插件，也不是可直接合入的补丁。**
> 配套设计说明见 [`../../docs/art-agent-orchestration-design.md`](../../docs/art-agent-orchestration-design.md)。
> 本目录不进 `src/`、不参与构建、不影响运行时，仅供维护者逐行对照后按本仓库四层结构重写。

## 1. 它是什么

一个曾运行在 maimai-drawpic-plugin 之上的**角色绘图编排插件**的代码快照。
它不负责出图，只负责把一句自然语言请求变成「抓哪些参考图 + 写什么提示词 +
每张图派什么用场」，再调用绘图插件的引擎。

⚠️ **本快照对应的是旧版「四通道 + 按引擎费用分流」实现**，与维护者商定后的
目标形态（外接绘图 Agent、统一出图接口、不保留按成本分流的多引擎通道）
**并不一致**。请把它当作下面这些机制的逐行参考，而不是照抄：

- 三级取图（段内 base64 → DB `raw_content` → 按 hash 读盘）；
- 会话参考图的**用途判定**（人物设定稿当身份基准并压过泛化图；场景图只取场景 / 光线 / 构图）；
- 单 `prompt` 画面模型的提示词契约（负面词反噬、正面描述、开放式引导）；
- 提示词分层 L1 / L2 / L3 与「Agent 自带提示词只写调用契约」；
- 任务可靠性：判路后只读预检、45 秒同句幂等、失败通知与回退。

四通道命名、引擎表、按单价分流这些部分**属于特定部署的历史约束，按商定结论不再保留**。

## 2. 文件

| 文件 | 内容 |
|---|---|
| `plugin.py` | 编排主逻辑：判路、三级取图、参考图用途判定、提示词拼装、幂等 / 失败回退 |
| `config.py` | 配置模型（Pydantic），字段与默认值 |
| `config.example.toml` | 行为契约样例：判路提示词、图源、预设、提示词模板。`api_key` 为空 |
| `search_ref.py` | 联网搜参考图 + 候选审核 |
| `_manifest.json` | 插件声明样例（标识与名称已中性化，仅作结构示例） |

## 3. 中性化处理

- 角色名及其拼音标识 → 「主角色」/ `example.art-orchestrator` 等通用词；
- **角色外貌设定整段替换为占位说明**（`config.example.toml` 的 `identity`、
  `config.py` 的 `SelfPromptsSection.identity` 默认值）；
- 具体出图成本、单价口径、预算估算 → 「按引擎计价 / 按实际用量计」；
- 引擎与通道的私有叫法 → 通用名称；
- 带日期的线上实测画面描述 → 中性表述；
- 不含真实凭据、实例 ID、私人号、本机路径、图片本体、会话历史、运行日志、额度数据。

`plugin.py` / `config.py` 里的 `0.12` 是**统计用单价常量**，属旧版实现的代码事实，
保留以免改动逻辑；它同样不代表通用建议。

## 6. 建议用法

1. 先读 `docs/art-agent-orchestration-design.md` 的 §0（商定结论）与 §1（目标形态）；
2. 再按 §8 的落地顺序，从「三级取图」和「提示词契约」两处挑需要的实现看；
3. 定下内置 LLM 的结构化输出契约（`references[].role`）后，按本仓库
   `domain / application / infrastructure / interfaces` 四层重写；
4. 全程遵循 `AGENTS.md`：`config_version`、i18n、`git diff --check`、测试、`build_webui.py`。
